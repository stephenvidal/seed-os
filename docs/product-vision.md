# Product vision — SEED OS

Source: owner's master directive (Directive v1.1). This is a faithful distillation, not a verbatim copy.

**Tagline:** From intention to execution.
**Category:** Autonomous Intelligence Workspace and Agent Execution Platform.

## Mission
A beautiful, sophisticated, self-hostable, model-agnostic agentic operating
environment. A user describes an outcome; SEED determines how to achieve it,
organizes the work, executes tools, coordinates specialists when useful,
verifies results, and delivers usable artifacts — with full visibility and
meaningful control, without the user managing implementation detail.

Not a static prototype, dashboard demo, or superficial chatbot. SEED must not
depend on Claude Code or Hermes Agent at runtime.

## Experience principle
**One assistant by default. An entire workforce when necessary.** The user talks
to one coherent assistant. Delegation to specialists is internal, inspectable,
and optional to interact with. Outcomes over agent theatrics.

SEED decides: what the user wants, what is known/missing, which actions and
tools are needed, whether specialists help, which permissions are required, how
to verify completion, and what to deliver.

## Identity
Brand ideas: intelligence, growth, precision, autonomy, reliability, clarity,
control, craftsmanship. A small intention becoming a meaningful result. No
literal botanical kitsch.

| Subsystem | Role |
|---|---|
| SEED Core | Agent runtime and execution engine |
| SEED Workspace | Primary web application |
| SEED Flow | Durable tasks, orchestration, workflows |
| SEED Studio | Artifacts, generated apps, previews |
| SEED Memory | Contextual knowledge and persistence |
| SEED Connect | Integrations and messaging gateways |
| SEED Control | Administration, policy, operations |

These are conceptual names, not mandatory services. No microservices to match branding.

## Design bar
World-class product craft; original design language (quality references: Linear,
Raycast, Vercel, Figma, Notion, GitHub — not templates). See `design-system.md`.

## Non-goals
- Dependence on a single commercial provider or on Claude Code/Hermes at runtime.
- Fake telemetry or scripted demos presented as agent capability.
- Intervention controls that are not implemented.
- Premature microservices.
